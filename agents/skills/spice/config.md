# Spice Configuration Architecture

Everything under `config/` is deployed to `~/.config/`. **Most dirs are stow
symlinks; `omarchy` is copied** (see `setup.md`). This guide covers the
Hyprland file chain, the Omarchy shell layout, installed plugins, themed
templates, hooks, the opencode config, and the `system/` directory.

## How Configs Reach the System

1. `install/config/stow.sh` wipes the target dirs (calibre, hypr, mpd,
   rmpc, sioyek, uwsm, yazi) and runs:
   ```bash
   stow --target="$HOME/.config" --ignore='^omarchy$' config
   ```
2. `install/config/omarchy.sh` then **copies** `branding`, `hooks`, `plugins`,
   `themed`, `shell.json` from `config/omarchy/` into `~/.config/omarchy/`.
3. Theme-derived symlinks (yazi theme, rmpc theme) are regenerated by the
   theme-set hooks.

Editing `~/.config/hypr/...` edits `config/hypr/...` (symlink), but editing
`~/.config/omarchy/...` does NOT touch the repo (copy) — edit the repo and
re-run `omarchy.sh`.

## Hyprland (`config/hypr/`)

`hyprland.lua` is the entry point. It bootstraps from Omarchy defaults, then
`require`s each personal file:

```lua
dofile((os.getenv("OMARCHY_PATH") or "/usr/share/omarchy") .. "/default/hypr/bootstrap.lua")
require("default.hypr.omarchy")
require("hypr.monitors")
require("hypr.input")
require("hypr.bindings")
require("hypr.looknfeel")
require("hypr.autostart")
require("hypr.rules")
require("default.hypr.toggles")
```

| File | Purpose |
|------|---------|
| `monitors.lua` | GDK_SCALE=1, monitor scale 1.25, `mode = "preferred"`, commented examples for per-monitor config + portrait rotation |
| `input.lua` | Input/keyboard settings |
| `bindings.lua` | Custom keybindings (below) |
| `looknfeel.lua` | Master layout, gaps 2, border 2, rounding 6, opacity, blur, Bibata cursor (24px) |
| `autostart.lua` | `o.exec_on_start("hyprsunset")` (battery-monitor was removed) |
| `rules.lua` | Window rules for Waydroid, Yazi, media-download, rmpc, wifi-qr, audacious + overview layer rules |
| `hyprsunset.conf` | Night light (hyprsunset) profiles |
| `xdph.conf` | XDG desktop portal config |
| `assets/` | Branding logos (`grabber.txt`, `push.txt`, `mp4-to-gif.txt`, ...) and helper lib used by bin/ scripts |

Note: the overview binding unbinds the Omarchy default (`hl.unbind`) before
rebinding, and calls `toggle overview` (the **short** plugin id — a previous
bug used the long `omarchy-overview` id, which the shell silently ignored).

#### Keybinding Quick Reference (read this FIRST)

- **File:** `config/hypr/bindings.lua` (stowed live — edits apply instantly
  with `hyprctl reload`, NO shell restart needed).
- **Syntax:** `o.bind("MODS + KEY", "Description", "command")` — defined in
  `/usr/share/omarchy/default/hypr/helpers.lua` (line ~81). `command` may be a
  plain string, a `hl.dsp.*` dispatcher, or a table like
  `{ launch = "cmd", focus = "^class$" }` / `{ webapp = "https://..." }`.
  Unbind defaults first: `hl.unbind("MODS + KEY")`.
- **KEY uses XKB keysym names, NOT abbreviations:** left Ctrl is
  `Control_L`, left Alt is `Alt_L` — `CTRL_L` / `ALT_L` fail with
  "Unknown keysym". Verify with: `hyprctl reload` → `hyprctl configerrors` →
  `hyprctl binds -j` (check the binding appears).
- **Fn key is NOT bindable on ThinkPads:** Fn is firmware/EC-level and never
  reaches Hyprland as a keysym (verified: `KEY_FN` bit 216 is absent from the
  AT keyboard keymap). Never suggest binding it.

### Restart the Shell After Major Changes (MANDATORY)

Hot-reload is NOT reliable for major shell/plugin changes. New plugin logic,
new profiles, new Process/daemon wiring, or stateful widget behavior can
silently fail to take effect while the shell keeps running — the log even
shows a clean reload while the widget still behaves as the old code. Real
example: the ThinkFan plugin's "Smart" profile showed as "balanced" and did
nothing until a full restart.

So after any major change to Omarchy shell/plugin code: **kill quickshell
and let Omarchy relaunch it.** Do NOT trust hot-reload for verification.

```bash
pgrep -a quickshell          # find instance, e.g. "667223 quickshell -n -p /usr/share/omarchy/shell"
kill <pid>                   # Omarchy auto-respawns (Hyprland autostart runs omarchy-launch-shell)
pgrep -a quickshell          # confirm new PID came up (must differ from killed one)
ls -td /run/user/1000/quickshell/by-id/*/ | head -1   # newest instance dir
tail -30 <dir>/log.log       # verify clean log, no errors for your plugin
```

If it does not come back: `omarchy restart shell` (or
`setsid omarchy-launch-shell`). Pre-existing unrelated warnings (e.g. missing
`opencode-zen.svg` in the agents plugin) are normal; only errors for YOUR
plugin/change matter.

## Themed Templates (`config/omarchy/themed/`)

Templates processed by `omarchy-theme-set-templates` on every theme change,
plus hook-generated outputs:

| File | Purpose |
|------|---------|
| `yazi.toml.tpl` | yazi theme template; `{{ key }}` placeholders filled by `update-yazi-theme` hook |
| `omarchy.ron.tpl` | rmpc theme template; `{{ accent }}`, `{{ foreground }}`, `{{ muted }}`, `{{ dark_background }}`, `{{ lighter_background }}` → `omarchy.ron` |
| `alacritty.toml.tpl.sample` | sample template for alacritty |

## Hooks (`config/omarchy/hooks/`)

| Directory | Contents |
|-----------|----------|
| `battery-low.d/` | `persistent-nag` (battery low nag handler) |
| `theme-set.d/` | `update-yazi-theme`, `update-rmpc-theme` |

Notable hooks:

- **`theme-set.d/update-yazi-theme`** — regenerates
  `~/.config/yazi/theme.toml` from `yazi.toml.tpl`, substituting `{{ key }}`
  placeholders using `omarchy-theme-color --file <colors.toml> --all` (the
  **full resolved** color set, including derived aliases like
  `dark_background`, `lighter_background`, `light_foreground`), then symlinks
  it. A previous bug substituted only raw `colors.toml` keys, leaving `{{ }}`
  literals that crashed yazi.
- **`theme-set.d/update-rmpc-theme`** — symlinks the generated
  `omarchy.ron` from the current theme state dir into
  `~/.config/rmpc/themes/omarchy.ron`.

Theme state dir: `~/.local/state/omarchy/current/theme/`.

## Common Tasks

- **Add a keybinding:** edit `config/hypr/bindings.lua`, then `hyprctl reload`
  — but remember the repo file is the source of truth.
- **Change bar layout:** edit `config/omarchy/shell.json`, then re-run
  `install/config/omarchy.sh` (or let the shell hot-reload) to push it live.
- **Add a plugin:** add the plugin dir under `config/omarchy/plugins/` and
  reference it in `shell.json`.
- **Add a hook:** drop an executable in the right `.d` directory under
  `config/omarchy/hooks/`.
- **Add a themed template:** put a `.tpl` in `config/omarchy/themed/`.
- **Tweak look & feel:** `config/hypr/looknfeel.lua` (gaps, blur, rounding,
  cursor).
